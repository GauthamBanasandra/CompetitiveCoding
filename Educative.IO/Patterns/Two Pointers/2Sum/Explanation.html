Why does the two-pointer sweep work?

The setup

We have a sorted array nums and a target. Place L at index 0 (smallest value) and R at index n - 1 (largest value). At every step compare sum = nums[L] + nums[R] against target:

sum == target → return (L, R) // done sum < target → L = L + 1 // need a bigger sum sum > target → R = R - 1 // need a smaller sum

The key invariant

At every iteration, the answer (if one exists) lies entirely inside the window [L, R]. Each move provably preserves this invariant by discarding one element that cannot belong to any valid pair.

Why "L++" when sum is too small is safe

Suppose nums[L] + nums[R] < target. Could nums[L] still pair with some element in [L+1, R-1]? No — because the array is sorted, every element in [L+1, R-1] is ≤ nums[R]. Their sum with nums[L] is at most nums[L] + nums[R], which is already less than target. So nums[L] can be eliminated:

∀ k in [L+1, R-1]: nums[L] + nums[k] ≤ nums[L] + nums[R] < target

Why "R--" when sum is too big is safe

Symmetric argument. If nums[L] + nums[R] > target, then nums[R] paired with anything in [L+1, R-1] gives a sum ≥ nums[L] + nums[R] > target. So nums[R] can never be part of a valid pair, and we drop it:

∀ k in [L+1, R-1]: nums[k] + nums[R] ≥ nums[L] + nums[R] > target

Why does it always terminate?

Each iteration either returns the answer or shrinks the window by exactly one. Starting from a window of size n, the loop runs at most n - 1 times before L meets R. That's O(n) time and O(1) extra space.

What if no pair exists?

The pointers eventually cross (L ≥ R) without ever satisfying sum == target. Because every discarded element was provably useless, crossing without a hit is a proof that no pair sums to the target.

Wait — isn't "Two Sum" usually solved with a hash map?

Yes! The famous LeetCode #1 ("Two Sum") works on an unsorted array, where the typical O(n) solution stores complements in a hash map. The two-pointer sweep requires the array to be sorted, which is exactly the condition of LeetCode #167 ("Two Sum II — Input Array Is Sorted"). If you're handed an unsorted array, sorting it first costs O(n log n), so for the unsorted case the hash map is faster — but the two-pointer version uses O(1) extra memory, which can matter in interviews and embedded settings.

The code (for reference)

def two_sum_sorted(nums, target): L, R = 0, len(nums) - 1 while L < R: s = nums[L] + nums[R] if s == target: return (L, R) elif s < target: L += 1 else: R -= 1 return None
