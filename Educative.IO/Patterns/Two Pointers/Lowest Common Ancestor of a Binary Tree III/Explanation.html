Why does the swap trick work?

The problem with just walking up

If p and q are at different depths, walking up from each at the same speed never lines them up — the deeper one will always be one step "behind" the shallower one. Two pointers walking up can pass right through the LCA at different times and never coincide.

The fix: equalize the path lengths

Define three distances along the tree:

a = distance(p → LCA)
b = distance(q → LCA)
c = distance(LCA → root)

So the full path from each node to the root is:

p → root takes a + c edges
q → root takes b + c edges

These are unequal whenever a ≠ b. That's exactly why naive walking fails.

The swap re-routes each pointer through the other

When ptr1 reaches root (its parent is None), we set ptr1 = q and continue. Same for ptr2. Now look at the full route each pointer takes before reaching the LCA:

ptr1: p ─(a+c)→ root ─(swap)→ q ─(b)→ LCA
ptr2: q ─(b+c)→ root ─(swap)→ p ─(a)→ LCA

Add up the steps for each:

ptr1 total = (a + c) + 1 + b = a + b + c + 1
ptr2 total = (b + c) + 1 + a = a + b + c + 1

Identical. Both pointers walk the same number of steps and arrive at the LCA on the same iteration, which is exactly when the loop's ptr1 == ptr2 check fires. The swap is just a slick way to make each pointer "pay" the depth-difference once, so the depths cancel out.

What if p is an ancestor of q?

Then LCA = p itself, so a = 0. ptr1 starts at the LCA but immediately walks away from it — that's fine. By the formula it returns to the LCA after b + c + 1 steps, which is exactly when ptr2 arrives there too via the swap. The trick still works.

Why doesn't it loop forever?

Each pointer follows a fixed finite route of length a + b + c + 1. After that step both are at the LCA, so the loop terminates. There is no infinite cycling because each pointer swaps at most once.

What if p and q are at the same depth?

Then a == b and the two pointers actually meet at the LCA after just a steps, before either one has to swap. The "+1 swap" detour is only needed to absorb a depth difference; when there's no difference, the swap is never reached. The algorithm gracefully handles this without any special case.

The code (for reference)

ptr1, ptr2 = p, q while ptr1 != ptr2: ptr1 = ptr1.parent if ptr1.parent else q ptr2 = ptr2.parent if ptr2.parent else p return ptr1
